# カードアニメーション機能

カードイラストをAIでアニメーション化するコスメティック機能の詳細設計。

> 関連: [マネタイズ強化 - カード強化版課金](./monetization-features.md)

---

## 機能概要

- ユーザーが所有するカードのイラスト（静止画）をAI動画生成モデルで短尺アニメーション化する
- ゲームプレイには影響しない**コスメティック（装飾）機能**
- アニメーション済みカードはコレクション画面やカード詳細で自動再生される
- 出力: 3〜5秒のループ動画（WebM / MP4）、解像度 512×768〜1024×1536程度

### ユーザー体験

1. カード詳細画面で「アニメーション化」ボタンをタップ
2. プレビュー（低解像度）を確認 → コイン消費して確定
3. 生成完了後、カード表示がアニメーション版に切り替わる
4. コレクション一覧ではサムネイルにアニメーションバッジを表示

### 推奨モデル

**第1候補: Kling 2.5/2.6**
- 理由: コストパフォーマンスが最も優れている（1回¥22程度）
- 1080p対応で十分な品質
- fal.ai / Replicate 経由でAPIアクセスが容易

**第2候補: Luma Ray 3**
- Klingより品質面で優れるケースがある
- 1回¥39と許容範囲内

**レアリティ別モデル使い分け（案）**

既存のカード画像生成と同様に、レアリティに応じてモデルを使い分ける選択肢もある:

| レアリティ | アニメーションモデル | 1回あたり原価 |
|-----------|---------------------|---------------|
| Common | Kling 2.5 | ¥22 |
| Rare | Luma Ray 3 | ¥39 |
| Super Rare | Runway Gen-4 | ¥90 |
| Legend | Runway Gen-4（長尺） | ¥120〜 |

→ ただし、アニメーション化はユーザーが任意に選ぶ機能のため、**全レアリティ統一モデル（Kling）の方がシンプル**で運用しやすい。

## コイン価格設計

### 前提: コイン経済

| パッケージ | コイン数 | 価格（税込） | 1コインあたり |
|-----------|---------|-------------|-------------|
| スタンダード | 600 | ¥980 | ¥1.63 |
| バリュー | 2,100 | ¥2,980 | ¥1.42 |
| プレミアム | 6,000 | ¥6,980 | ¥1.16 |

**加重平均: 1コイン ≒ ¥1.2〜1.6**（ユーザーの購入プランによる）

### 原価とマージン計算

Kling使用時（1回¥22の原価）を基準:

| コイン設定 | 円換算（バリュー基準¥1.42/coin） | 原価率 | 粗利率 |
|-----------|--------------------------------|--------|--------|
| 50コイン | ¥71 | 31% | 69% |
| 80コイン | ¥114 | 19% | 81% |
| 100コイン | ¥142 | 15% | 85% |
| 150コイン | ¥213 | 10% | 90% |

### 提案: **80コイン**

- **原価率19%** — 画像生成サービスの業界標準的なマージン（粗利80%前後）
- カード生成（30コイン）の約2.7倍で、「特別な体験」としての価格感がある
- 無料ユーザーの1日分コイン（90コイン）でほぼ1回分 → 毎日1枚アニメ化できる程度
- プレミアムユーザー（日300コイン）なら1日3〜4枚 → コレクター欲を刺激

### 比較: 既存コスト感

| 機能 | コイン消費 |
|------|----------|
| カード生成 | 30 |
| チャレンジ追加 | 10 |
| **アニメーション化** | **80（提案）** |

→ カード生成より高いが、既存の「アニメーション 500コイン」（monetization-features.md の案）は高すぎる。80コインなら気軽に試せる価格帯。

## 技術的な検討事項

### ストレージ

- 出力動画はGCS `animations/` プレフィックスに保存
- 5秒 × 1080p WebM ≒ 1〜3MB/ファイル
- サムネイル用にGIFまたは先頭フレーム画像も生成

### データモデル拡張

```prisma
// Card モデルに追加
model Card {
  // ... 既存フィールド
  animationUrl    String?   // アニメーション動画URL
  animationStatus String?   // "processing" | "completed" | "failed"
  animatedAt      DateTime?
}
```

既存の `CardEnhancement` テーブル（monetization-features.md参照）を使う方法もあるが、アニメーションは1カードに1つなので Card モデルへの直接追加がシンプル。

### API

```
POST /api/cards/:id/animate    — アニメーション生成リクエスト
GET  /api/cards/:id/animate    — 生成状態確認（ポーリング用）
```

### フロントエンド表示

- カード詳細: `<video>` タグでループ自動再生（muted, autoplay, loop, playsinline）
- コレクション一覧: ホバー時のみ再生（パフォーマンス考慮）
- モバイル: タップで再生トグル

**実装難易度**: ★★☆☆☆（外部API呼び出し + ストレージ保存のパターンは既存の画像生成と同じ）

**推奨フェーズ**:
1. まずKling単一モデルで全レアリティ対応（MVP）
2. ユーザー反応を見てレアリティ別モデル分岐を検討
3. 将来的にはカスタムプロンプト（「炎エフェクト追加」等）も検討可能
